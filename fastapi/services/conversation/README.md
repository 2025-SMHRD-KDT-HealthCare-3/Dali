# conversation — 깔때기 전체 흐름 단계

대화가 사용자 입력에서 출력까지 거치는 **깔때기 전체 흐름**을 담는 폴더다.
(현재는 흐름 정의만 둔다. 단계별 코드/문서 산출물은 추후 이 폴더에 추가한다.)

## 전체 흐름 (CLAUDE.md '핵심 데이터 흐름' — 절대 변경 금지)

```
사용자 입력
   ↓
FastAPI + KoELECTRA (감정 분석)              ← 타 파트(에스라)
   ↓
사용자 입력 + 분석값   ← 깔때기 목
   ↓
[위험 판정]                                  ← 타 파트(백엔드·준하)
   ├─ 위험 → LLM 건너뜀 → 고정 안내 문구 → 사용자
   └─ 안전 → LLM → 공감 답변 → 사용자        ← 여기부터 LLM 파트(우리)
```

## 단계별 담당 경계

| 단계 | 내용 | 담당 |
|---|---|---|
| 1. 입력 | 감정 이모지 선택 → 텍스트/음성 입력 | 프론트(정인) / STT |
| 2. 감정 분석 | KoELECTRA 감정 6종 분석 | 에스라 |
| 3. 깔때기 목 | 입력 + 분석값 묶음 (계약 형식만 합의) | 경계 |
| 4. 위험 판정 | 위험/안전 분기 | 백엔드(준하) |
| 5-a. 위험 | LLM 건너뜀 → 고정 안내 문구 | 백엔드(준하) |
| **5-b. 안전 → 공감 답변** | **안전 입력만 LLM으로, 페르소나 공감 대화** | **LLM 파트(우리)** |
| 6. 종료 후 | 리포트 + 회복(행동) 미션 생성 | LLM 파트(우리) |

## 이 폴더에서 우리가 다루는 범위

- **5-b 이후만** 우리 작업이다. 위험 키워드 검사는 LLM 프롬프트에 넣지 않는다
  (깔때기 상위에서 처리, "안전" 통과 입력만 받는다는 전제).
- LLM 입력값 조립(온보딩 + 오늘 감정 + 현재 대화 + 최근 7일 요약 + 세션 감정 요약)도
  이 흐름의 일부로, 추후 `pipeline/`과 함께 이 폴더에 설계를 정리한다.

> 미확정: 단계별 세부 산출물(입력 조립 코드, 응답 검증 단계 등)은 별도 설계로 채운다.
